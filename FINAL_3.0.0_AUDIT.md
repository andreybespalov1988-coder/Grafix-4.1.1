# Графикс 3.0.0 — полный цикл аудита и доработки

Дата: 23.09.2026

## A. Что найдено

Текущая 2.2.9 имела зрелый local-first фундамент: Electron, атомарное файловое хранение, backup/recovery, импорт/экспорт, ручное составление, печатный редактор, публичное расписание/Tilda и проверки конфликтов.

Главный функциональный разрыв с зрелыми планировщиками — отсутствие полноценного автоматического составления. У Untis автоматический генератор использует доступность и взвешенные критерии, у Prime есть автоматический генератор и модель ограничений, у FET — автоматическая генерация и очень широкая система временных/пространственных ограничений. Это подтверждено официальными материалами конкурентов.

## B. Что изменено

### P0
- Добавлено автоматическое локальное составление расписания.
- Добавлены жёсткие проверки пересечений педагога, группы и кабинета.
- Учитываются недоступность педагога, рабочие часы и дневные лимиты.
- Добавлено мягкое предпочтение компактного расписания.
- Генератор формирует до трёх вариантов и объясняет незапланированные занятия.
- Закреплённые занятия не перемещаются.
- Введена безопасная структурированная модель ссылок teacherId/groupId/roomId/subjectId/programId при сохранении старых текстовых полей для обратной совместимости.

### P1
- Раздел «Аналитика».
- Расчёт нагрузки педагогов.
- История последних изменений.
- Централизованные правила расписания.
- Миграция данных старых проектов в новые структурированные ссылки.

### P2
- Основа для дальнейшего календаря/циклов заложена в расширенной модели данных, но полноценный учебный год и многонедельные циклы не объявляются реализованными.

### P3
- Не повышались выше стабильности: облачная совместная работа, роли, live-publication через сервер, полноценный AI-провайдер, мобильный PWA.

## E. Что улучшено относительно конкурентов

Главное отличие 3.0.0 — генератор работает полностью локально и сразу показывает пользователю причины невозможности размещения, а не только итог «не удалось». При этом ручной редактор и существующая печать/Tilda не заменяются новым режимом.

## G. Что невозможно проверить в текущей среде

- Windows installer/portable build: `electron` и `electron-builder` отсутствуют в текущем runtime, а установка зависимостей не завершилась в доступное время.
- Реальная публикация Tilda без внешней сети/учётной записи.
- Реальная совместная работа/авторизация, PostgreSQL и серверные API — в текущем продукте отсутствуют серверные компоненты.
- AI API — внешний ключ/провайдер не подключён.

## J. Известные проблемы

- Генератор 3.0.0 — эвристический локальный генератор, а не промышленный constraint solver уровня FET/Untis. Для очень больших расписаний потребуется отдельный оптимизационный слой.
- XLSX пока отсутствует.
- Серверная безопасность не может быть названа production-ready, потому что серверного контура в local-first приложении нет.
- UI использует inline handlers и большой single-file renderer; для дальнейшего масштабирования стоит постепенно разделить renderer на модули без одномоментного переписывания.

## K. Запуск

Для исходников с установленными зависимостями:

```text
npm install
npm start
```

Windows release:

```text
npm install
npm run dist:win
```

В текущем runtime сборка Windows не выполнена из-за отсутствующих npm-зависимостей.
