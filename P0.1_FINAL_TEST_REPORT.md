## Root causes found

The real Windows evidence showed that `or-tools-wasm@0.9.1` installed and imported successfully, but the worker used a mixed JavaScript API. The first runtime failure was `vars[i].mul is not a function`. Timeout handling then attempted to read a non-solution literal through `booleanValue()`.

## Corrections

1. `plus()` replaces unsupported `add()` expression chaining.
2. `times()` replaces unsupported `mul()` calls.
3. `addLinearConstraint()` replaces unsupported `addLessOrEqual()` for exact no-good cuts.
4. Solution extraction uses `solver.value(BoolVar)` and never calls `booleanValue()` on numeric literals.
5. `solver.solve(model)` is called with configured `solver.parameters`; an AbortSignal is no longer passed as a fake solver parameter.
6. Timeout/cancellation uses the public `CpSat.cancelSolve()` API.
7. A solver result is only exposed as `bestKnown` when a readable assignment actually exists; no placeholder objective/penalty/violation values are fabricated when no solution exists.
8. Added a real CP-SAT API smoke test and a static guard against the known incompatible worker calls.
9. Added the new gates to the solver foundation suite.
