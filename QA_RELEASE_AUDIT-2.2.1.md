# QA / Release Audit — Графикс 2.2.1

Дата аудита: 22.09.2026
Целевая платформа: Windows 11 desktop

## Итог

**NOT READY — release candidate, не финальный Windows release.**

Причина единственная, но блокирующая для заявления о полном production-релизе: в текущем окружении отсутствует доступ к npm registry и отсутствуют установленные Electron/electron-builder. Поэтому реальный Electron runtime, NSIS installer, portable EXE и установочный цикл Windows физически не были выполнены.

Исходный код после исправлений прошёл полный доступный автоматический QA-проход.

- архитектура main/preload/renderer/storage;
- IPC-контракт сохранения;
- атомарная запись и backup/recovery;
- сохранение после перезапуска;
- A4 print static checks;

## Найденные проблемы и исправления

### HIGH-01 — Tilda-код фактически не генерировался

Причина: в шаблоне `buildPublicEmbed()` использовался идентификатор `e` из будущего генерируемого скрипта на этапе формирования самого шаблона. Это вызывало `ReferenceError: e is not defined`, после чего catch очищал textarea.

Исправление: значения, которые должны попасть в Tilda-код из приложения, теперь экранируются функцией renderer `esc()`. Генерируемый код использует свою локальную `e()` только после публикации.

Проверка: `public_runtime_test.js` — PASS.

### HIGH-02 — предпросмотр публичного расписания мог завершаться пустым блоком

Исправление: предпросмотр теперь является самостоятельным этапом. При пустом наборе показывается явное состояние, при исключении — техническая ошибка в статусе. Генерация Tilda-кода не может скрыть ошибку предпросмотра.

Проверка: `public_runtime_test.js` — PASS.

### HIGH-03 — редактор печати не давал удобного интерактивного изменения размеров

Исправление: добавлены числовые размеры в мм и drag-resize:
- ширина столбцов — 12–100 мм;
- высота строк — 5–60 мм;
- размеры сохраняются в `printSettings`;
- размеры можно менять непосредственно на листе через grip.

Проверка: `print_editor_runtime_test.js` — PASS.

### MEDIUM-01 — Undo/Redo не гарантировал сохранение восстановленного состояния на диск

Исправление: восстановленное через Undo/Redo состояние теперь проходит через единый `baseSave()` и записывается на диск.

Проверка: существующие storage/restart tests — PASS; отдельный Electron runtime тест остаётся заблокирован отсутствием Electron.

### MEDIUM-02 — принудительный scale factor 1 ломал Windows DPI scaling

Исправление: удалён `force-device-scale-factor=1`. Теперь Windows/Electron используют системный DPI scale.

Это важно для 125%, 150% и 200% масштабирования.

## Security audit

Проверено:

- `nodeIntegration: false` — включено;
- `contextIsolation: true` — включено;
- внешняя навигация блокируется;
- `window.open` блокируется;
- в renderer/main/storage не обнаружены `eval`, `new Function`, `child_process`, `shell.openExternal`, `fetch`, `WebSocket` и аналогичные внешние каналы;
- секреты/API keys в исходниках не обнаружены;
- renderer получает только явно опубликованный preload API;
- запись файлов выполняется через main process;
- atomic storage использует временный файл + fsync + rename;
- повреждённый primary восстанавливается из backup.

Ограничение: полноценный `npm audit` невозможен без доступа к registry и установленных зависимостей.

## Производительность

Проверены статически:

- отсутствие очевидных сетевых запросов;
- отсутствие тяжёлых сторонних runtime-библиотек;
- Tilda payload сжимается gzip при наличии `CompressionStream`;
- есть UTF-8 Base64 fallback;
- payload не содержит Base64 логотипа организации, чтобы не раздувать код Tilda.

Не выполнено физически:

- RAM/CPU/GPU профилирование Electron процесса;
- длительный soak test;
- тестирование больших расписаний в реальном Electron renderer.
